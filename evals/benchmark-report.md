# Dramake v0.4.0 验证报告

日期：2026-08-26

本版本使用 20 个代表性场景检查指令覆盖，并使用确定性测试验证文档结构、模板字段、版本同步和计划门禁。

## 覆盖场景

1. 90 秒真人家庭短剧、用户自选执行入口与费用上限；
2. 3 分钟单元剧、常驻角色声线与原生对白；
3. 服装、手机方向和玻璃穿透错误的父段门禁；
4. 执行入口可替换；
5. 10 秒一句话后站桩的节奏修复；
6. 非写实 2D 漫剧；
7. 未明确上传/费用边界的并行付费请求；
8. 产品文字变异与额外手指；
9. 真人环境中的写实可爱宠物；
10. 小白从 300 字故事开始；
11. 无动机堆叠推拉摇移环绕；
12. 同一女主跨片段声线漂移；
13. 跨地点/时间却错误要求尾帧无缝续写；
14. 同一故事的抖音 9:16 与 YouTube 16:9 版本。
15. 抖音 90 秒高密度节奏重写，同时禁止把有效节拍误拆成大量 5 秒生成片段。
16. Wan 3 混合参考、多角色原生对白、无配乐音轨、首尾帧互斥与输入视频时长预算。
17. 重复/文字道具跨幕漂移、倒车/转向/脱落物理失败，以及碰撞镜头缺少感官冲击的通用修复工作流。
18. 萌宠自助餐从自然触发事件到主反转的宏观因果链，以及背景反应角色；
19. 三文鱼落头笑点的视线盲区、观众信息优势、反应停顿与主线后果；
20. 写实世界中的动画演员式猫咪表演、道具物理锁与工作人员/猫咪嘴型绑定。

## 确定性检查

仓库测试会检查：

- 中英文镜像、Skill/CITATION/README 版本一致；
- 主 Skill 行数与通用内容范围；
- 连续性、重复道具、生成段、镜头、声线、音频和费用模板字段；
- 未验收父段不得解锁、20–30 秒长段节拍不能过稀；
- 镜头不得超过生成段时长、引用声线必须存在；
- 接触段必须有物理事件合同，冲击镜头必须有完整冲击结构；
- 喜剧段必须有宏观目标、因果贡献、事件负载、笑点合同和三个以上表演状态；
- 活跃说话者必须有明确声源、唯一嘴型主体、非说话者闭嘴状态与轮次；
- 质量档不能冒充付费授权；
- 已移除的品牌、说明页与旧命名不得残留公开文件。

## 验证边界

这些检查验证的是 Skill 的指令覆盖、文件一致性和计划约束，不是对任一模型最终视频质量的保证。模型能力、价格和参数必须在执行时核实；候选质量必须检查真实媒体、音频、抽帧、物理与冷观众结果。没有真实候选证据时，不给出“已通过成片质量”的结论。
